The routine I run on every bug

01

Check the repo is alive

One command before I read any code. Archived, or nothing pushed in about six months, means a PR goes nowhere.

$ gh repo view org/repo --json isArchived,pushedAt
02

Use it like a user

I build the tool and run it on a real use case. Every place it fights me goes in a log. Silent failures, hangs and races first, style nits last.

# friction log, one line per snag
03

Search for duplicates

The moment I think I have a bug, I search issues and open PRs. This happens before I write any fix.

$ gh search issues "symptom" --repo org/repo $ gh pr list --repo org/repo --search "symptom"
04

Read CONTRIBUTING

All of it, every time. If it says wait to be assigned, I open the issue and wait.

# CONTRIBUTING.md, to the end
05

Smallest fix, plus the test

Match the repo style. Add the test that fails before the fix and passes after. Keep the real terminal output, before and after.

$ pytest tests/test_bug.py # red, then green
06

Run /review

A fresh agent that did not write the fix re-clones the repo, re-runs my repro from scratch, and tries to prove it is intended behavior. It also checks every "other tools do it this way" claim against a real source. I fix what it finds before anything is posted.

/review # clean clone, independent red-team
07

Defend it cold

A mock maintainer of that exact repo grills me on the diff. I answer in my own words. A line I cannot explain does not ship.

# no notes, no autocomplete
08

Post it short

Conventional commit. PR body with the real output. Comments in my own voice, after checking the repo's AI policy. Limits stated plainly. Then I stay for CI and review.

$ gh pr create
